## 快速開始

### 第一次使用

1. **找到 Bot**
   - 在 Telegram 搜尋你的 Bot 名稱
   - 或使用 Bot 的 username（例如：@YourParkingBot）

2. **開始對話**
   ```
   /start
   ```
   你會看到歡迎訊息和功能介紹

3. **初始配置**
   ```
   /setup
   ```
   按照提示完成以下設定：
   - 輸入 TDX API 金鑰
   - 輸入 Supabase 連線資訊
   - 確認配置成功

4. **開始使用**
   - 配置完成後，就可以使用所有功能了！

## 功能詳解

### 1. 停車位搜尋 (`/parking`)

#### 使用步驟

1. **啟動搜尋**
   ```
   /parking
   ```

2. **提供位置**
   
   方式 A：分享 Telegram 位置
   - 點擊「📍 分享當前位置」按鈕
   - 允許 Telegram 存取位置
   
   方式 B：提供 Google Maps 連結
   - 開啟 Google Maps
   - 長按地圖上的位置
   - 點擊「分享」→ 複製連結
   - 貼到 Bot 對話中

3. **選擇搜尋半徑**
   - 500 公尺：步行範圍
   - 1 公里：短距離
   - 2 公里：較大範圍

4. **查看結果**
   
   Bot 會顯示：
   - 停車場名稱
   - 距離（公尺）
   - 剩餘車位 / 總車位
   - 收費資訊
   - 導航連結

#### 結果範例

```
🅿️ 找到 5 個停車場

📍 台北市政府地下停車場
距離：350 公尺
剩餘車位：45 / 200
收費：每小時 30 元
[📍 導航](https://maps.google.com/...)

📍 市民大道路邊停車
距離：420 公尺
剩餘車位：8 / 20
收費：每小時 40 元
[📍 導航](https://maps.google.com/...)
```

#### 使用技巧

- 🎯 **精確搜尋**：使用 Google Maps 連結可以指定確切位置
- 🚶 **步行距離**：選擇 500m 半徑最適合步行
- 🚗 **開車範圍**：選擇 1-2km 半徑適合開車前往
- 🔄 **重新搜尋**：如果結果不滿意，可以點擊「重新搜尋」

---

### 2. 車流查詢 (`/traffic`)

#### 使用步驟

1. **啟動查詢**
   ```
   /traffic
   ```

2. **提供路線**
   
   取得 Google Maps 路線連結：
   - 開啟 Google Maps
   - 點擊「路線」
   - 輸入起點和終點
   - 點擊「分享」→ 複製連結
   - 貼到 Bot 對話中

3. **查看結果**
   
   Bot 會顯示：
   - 路線距離
   - 預估時間
   - 整體車流狀況（🟢順暢 / 🟡壅塞 / 🔴嚴重壅塞）
   - 交通事故資訊

#### 結果範例

```
🚗 路線車流狀況

距離：75.2 公里
預估時間：85 分鐘

整體狀況：🟡 壅塞

⚠️ 交通事故
類型：車輛故障
說明：國道 1 號 50K 處，外側車道
預估影響：+15 分鐘
```

#### 使用技巧

- 🕐 **出發前查詢**：建議出發前 10-15 分鐘查詢
- 🔄 **即時更新**：車流資訊每 5 分鐘更新
- 💡 **加入路線**：可以將常用路線加入經常性路線，接收主動通知
- 🚨 **注意事故**：紅色標示的事故影響較大，建議改道

### 3. 經常性路線管理 (`/routes`)

#### 功能說明

設定常用路線後，Bot 會自動監控車流狀況，在發生異常時主動通知你。

#### 使用步驟

##### 新增路線

1. **開啟路線管理**
   ```
   /routes
   ```

2. **選擇「➕ 新增路線」**

3. **輸入路線名稱**
   ```
   上班路線
   ```
   或
   ```
   回家路線
   ```

4. **提供路線 URL**
   - 從 Google Maps 複製路線規劃連結
   - 貼到 Bot 對話中

5. **設定通知偏好**
   - ✅ 啟用：發生異常時會收到通知
   - ❌ 不啟用：僅儲存路線，不發送通知

##### 查看路線

1. 選擇「📋 查看路線」
2. 查看所有已儲存的路線資訊

##### 編輯路線

1. 選擇「✏️ 編輯路線」
2. 選擇要編輯的路線
3. 輸入新的路線名稱

##### 刪除路線

1. 選擇「🗑️ 刪除路線」
2. 選擇要刪除的路線
3. 確認刪除

#### 通知範例

當路線發生異常時，你會收到：

```
⚠️ 路線異常通知

您的經常性路線「上班路線」出現異常：

🔴 嚴重壅塞
預估時間：比平常多 30 分鐘

🚨 重大事故
位置：國道 1 號 50K
類型：多車追撞
建議改道或延後出發
```

#### 使用技巧

- 📍 **最多 5 條**：每個使用者最多可設定 5 條經常性路線
- 🔔 **通知時段**：可以設定只在特定時段接收通知（未來功能）
- 🚫 **通知去重**：相同事件 30 分鐘內不會重複通知
- ⏰ **監控頻率**：系統每 15 分鐘檢查一次路線狀況

### 4. 配置管理

#### 查看配置 (`/config`)

顯示當前配置狀態：
- TDX API 金鑰狀態
- Backend 類型
- 配置時間

```
📋 當前配置

✅ TDX API 金鑰：已設定
🔧 Backend 類型：supabase
📅 配置時間：2024-01-15 10:30:25
```

#### 重置配置 (`/reset`)

⚠️ **警告**：重置會清除所有資料，包括：
- API 金鑰
- Backend 設定
- 所有經常性路線

使用步驟：
1. 輸入 `/reset`
2. 確認重置
3. 重新執行 `/setup` 配置

## 使用技巧

### 1. 位置輸入技巧

#### 使用 Telegram 位置
- ✅ 優點：快速、準確
- ❌ 缺點：需要開啟位置權限

#### 使用 Google Maps 連結
- ✅ 優點：可以指定任意位置
- ✅ 優點：不需要位置權限
- 💡 技巧：可以搜尋地址後分享

### 2. 搜尋半徑選擇

| 半徑 | 適用情境 | 結果數量 |
|------|----------|----------|
| 500m | 步行、附近停車 | 較少但精準 |
| 1km | 短距離開車 | 適中 |
| 2km | 較大範圍搜尋 | 較多選擇 |

### 3. 節省 API 用量

- 🔄 **使用快取**：5 分鐘內重複查詢會使用快取
- 📍 **精確位置**：提供精確位置可減少重複搜尋
- ⏰ **合理頻率**：避免短時間內重複查詢

### 4. 最佳使用時機

#### 停車位搜尋
- 🕐 **到達前 5-10 分鐘**：確保資訊最新
- 🚗 **開車途中**：可以請副駕駛協助查詢

#### 車流查詢
- 🕐 **出發前 10-15 分鐘**：掌握即時路況
- 🔄 **途中更新**：長途旅程可中途再查詢

#### 經常性路線
- 🏠 **通勤路線**：設定上下班路線
- 🚗 **常用路線**：設定經常往返的路線

## 常見問題

### Q1: 找不到停車場資訊？

**可能原因**：
- 該區域沒有提供即時資訊
- TDX API 暫時無法使用
- 搜尋半徑太小

**解決方法**：
- 擴大搜尋半徑
- 稍後再試
- 更換搜尋位置

### Q2: 車流資訊不準確？

**說明**：
- 車流資訊來自 TDX API，更新頻率約 5 分鐘
- 實際路況可能有變化
- 建議作為參考，不要完全依賴

### Q3: 沒有收到通知？

**檢查清單**：
- ✅ 確認已啟用路線通知
- ✅ 確認 Telegram 通知權限已開啟
- ✅ 確認路線確實有異常（嚴重壅塞或重大事故）
- ✅ 確認不在 30 分鐘通知冷卻期內

### Q4: API 金鑰無效？

**解決方法**：
1. 確認金鑰複製完整（很長的字串）
2. 檢查 TDX 平台金鑰狀態
3. 重新申請金鑰
4. 使用 `/reset` 重新配置

### Q5: Bot 回應很慢？

**可能原因**：
- TDX API 回應慢
- 網路連線問題
- Bot 伺服器負載高

**解決方法**：
- 稍等片刻（最多 10 秒）
- 檢查網路連線
- 如果持續緩慢，請回報問題

### Q6: 如何更新配置？

**方法 1**：重置後重新配置
```
/reset
/setup
```

**方法 2**：直接執行 setup（會覆蓋舊配置）
```
/setup
```

### Q7: 可以同時查詢多個位置嗎？

**答**：目前不支援。每次只能查詢一個位置，但可以：
- 快速切換查詢不同位置
- 設定多條經常性路線（最多 5 條）

### Q8: 資料會保存多久？

**保存期限**：
- 使用者配置：永久（除非重置）
- 經常性路線：永久（除非刪除）
- 通知記錄：30 天
- 快取資料：5 分鐘

## 隱私與安全

### 資料收集

Bot 只收集必要資訊：
- Telegram User ID（用於識別使用者）
- TDX API 金鑰（加密儲存）
- 經常性路線資訊
- 通知記錄

### 資料安全

- 🔐 API 金鑰使用 AES-256 加密
- 🔒 資料儲存在 Supabase（符合 GDPR）
- 🚫 不會分享給第三方
- 🗑️ 可隨時使用 `/reset` 清除所有資料

### 位置隱私

- 📍 位置資訊不會被儲存
- 🔍 只用於即時查詢
- 🚫 不會追蹤使用者位置
